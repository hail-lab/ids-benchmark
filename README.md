# Failure Modes in Machine Learning-Based Intrusion Detection: Leakage Inflation, Multi-Class Collapse, and Dataset-Specific Feature Dependence

## Overview

This repository implements a controlled audit of evaluation assumptions in
machine learning-based network intrusion detection. Eight ML/DL models are
evaluated across three standard IDS datasets (CICIDS2017, ToN-IoT, UNSW-NB15)
under identical leakage-controlled preprocessing and five-fold stratified
cross-validation for both binary and multi-class tasks (48
model-dataset-task combinations). Rather than proposing a new detector, the
study isolates and quantifies three reproducible failure modes that distort
headline IDS performance numbers reported in the literature.

**Paper:** *Failure Modes in Machine Learning-Based Intrusion Detection:
Leakage Inflation, Multi-Class Collapse, and Dataset-Specific Feature
Dependence* - submitted to *Heliyon*.

**Authors:** S. Aljaloud and A. Alshammari, University of Ha'il, Saudi Arabia.

---

## Results Summary

| Failure Mode | Key Result |
|---|---|
| **Failure Mode I - Identifier Leakage Inflation** | Median absolute F1 inflation 0.018 (binary), 0.092 (multi-class); max 0.39 absolute (68% relative; k-NN on ToN-IoT multi-class); dose-response with identifier richness |
| **Failure Mode II - Multi-Class Collapse** | LightGBM CICIDS2017: F1 = 0.998 (binary) -> 0.197 (multi-class); replicated across 3 alternative configurations |
| **Failure Mode III - No Universal Feature Set** | Disjoint top-20 SHAP rankings across datasets: TCP window features (CICIDS2017), Zeek metadata (ToN-IoT), TTL-based features (UNSW-NB15) |
| **Feature-Selection Ablation** | 80% feature reduction with < 0.4% F1 loss across all datasets |
| **Friedman / Nemenyi** | Tree ensembles dominate the configuration tested; the gap to deep models is configuration-dependent and reported as a secondary observation |

## Reproduction

### 1. Install dependencies

```
pip install -r requirements.txt
```

### 2. Download datasets

```
python src/data_collection.py
```

This prints manual download instructions for each dataset. Place the
downloaded files in `data/raw/`:

| Dataset | Source | Rows | Classes | Year |
|---|---|---|---|---|
| **CICIDS2017** | [UNB CIC](https://www.unb.ca/cic/datasets/ids-2017.html) | ~2.8M | 15 | 2017 |
| **ToN-IoT** | [UNSW](https://research.unsw.edu.au/projects/toniot-datasets) | ~460K | 10 | 2020 |
| **UNSW-NB15** | [UNSW](https://research.unsw.edu.au/projects/unsw-nb15-dataset) | ~2.5M | 10 | 2015 |

### 3. Preprocess all datasets

```
python src/preprocessing.py
```

The preprocessing module drops identifier columns (IPs, ports, flow IDs,
timestamps) by default. The same script with `LEAKAGE_PATTERNS=[]` produces
the leaky parquet used in Failure Mode I; see step 7.

### 4. Train all models (8 models x 3 datasets x 2 tasks = 48 combinations)

```
python src/train_all.py
```

Training is resumable: completed (model, dataset, task) combinations are
skipped on re-run by checking `outputs/tables/benchmark_results.csv`.

### 5. Post-training analysis

```
python src/post_training.py
python src/ablation.py
python src/friedman_cd.py
python src/confusion_matrices.py
```

### 6. Generate figures and SHAP analysis

```
python src/evaluation.py --shap
```

### 7. Leakage experiment and LightGBM validation

```
python src/leakage_comparison.py
python src/lgbm_validation.py
python src/lgbm_validation_ova.py
```

### 8. Generate LaTeX tables

```
python src/gen_latex_tables.py
```

All outputs (CSV tables, PDF figures) are saved to `outputs/tables/` and
`outputs/figures/`.

### Selective runs

```
python src/preprocessing.py --dataset cicids2017
python src/train_all.py --dataset cicids2017 --model XGBoost
python src/ablation.py --cross-dataset
python src/ablation.py --fs-ablation
```

### Optional: fourth-dataset validation (CSE-CIC-IDS2018)

A Colab notebook at `notebooks/csecic2018_validation.ipynb` reproduces the
three failure-mode checks on CSE-CIC-IDS2018 as an external robustness probe.
This is independent of the main paper pipeline and is provided for reviewers
or readers who wish to extend the audit to a fourth dataset.

## Analysis Code (`src/`)

### Data Collection and Preprocessing
- `data_collection.py` - prints download URLs and instructions for all datasets
- `preprocessing.py` - unified cleaning pipeline: drops leakage columns (IPs, ports, flow IDs, timestamps) by default; toggleable via `LEAKAGE_PATTERNS` for the controlled-leakage experiment; encodes labels; outputs parquet
- `utils.py` - shared paths, logging configuration, and constants (`DATASETS`, `MODEL_NAMES`, `METRICS`)

### Model Training
- `train_all.py` - resumable driver that trains all 8 models (XGBoost, Random Forest, LightGBM, SVM, k-NN, MLP, 1D-CNN, BiLSTM) with 5-fold stratified CV; writes results to `outputs/tables/benchmark_results.csv` and skips already-completed combinations on re-run
- `model.py` - per-model implementation called by `train_all.py`

### Evaluation and Analysis
- `evaluation.py` - generates performance figures (grouped bars, heatmaps, scatter plots) and SHAP beeswarm plots
- `post_training.py` - computes per-class F1, binary-to-multi-class degradation, and Wilcoxon signed-rank tests
- `ablation.py` - feature-selection ablation (MI + RF hybrid) and cross-dataset transfer analysis
- `friedman_cd.py` - Friedman test with Nemenyi post-hoc and Critical Difference diagrams
- `confusion_matrices.py` - normalised confusion matrix heatmaps for multi-class results

### Failure-Mode Experiments
- `leakage_comparison.py` - compares clean vs. leaky (identifier-retaining) results; computes per-(model, dataset, task) F1 inflation deltas; generates leakage-impact bar charts (Failure Mode I)
- `lgbm_validation.py` - validates the LightGBM multi-class collapse through alternative configurations (Failure Mode II)
- `lgbm_validation_ova.py` - LightGBM one-vs-all validation experiment (Failure Mode II)

### Utilities
- `gen_latex_tables.py` - auto-generates LaTeX table code from result CSVs

## Output Files

### Figures (used in paper)
- Grouped bar charts (binary + multi-class F1)
- SHAP beeswarm plots (x3 datasets) - Failure Mode III evidence
- Training time vs. F1 scatter plots
- Feature-selection ablation curves (x3 datasets)
- Critical Difference diagrams (binary + multi-class)
- Leakage comparison bar charts (x3 datasets, binary + multi) - Failure Mode I evidence
- Confusion matrices (x3 datasets, multi-class) - Failure Mode II evidence

### Tables
- `benchmark_results.csv` - full 48-combination benchmark (F1, precision, recall, training time)
- `leakage_comparison.csv` - clean vs. leaky performance with absolute and relative inflation
- `ablation_feature_selection.csv` - F1 at each feature count
- `degradation_table.csv` - binary-to-multi-class F1 degradation per model
- `friedman_results.csv` - Friedman test statistics and p-values
- `lgbm_validation.csv` - LightGBM alternative configuration results
- `per_class_f1.csv` - per-class F1 scores for all models
- `wilcoxon_results.csv` - Wilcoxon signed-rank test results
